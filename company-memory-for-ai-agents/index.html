Company memory for AI agents: many writers, many readers, one set of rules

Most writing about agent memory follows one agent remembering its own work. We build agents that share one memory of a customer's company, and that memory needs different rules.

By Eason Wang, Co-Founder & CPO, SolCrys

Updated 2026-11-07

Questions this guide answers

  • What is company memory for AI agents?
  • How is an agent's memory of a company different from its memory of a person?
  • Should AI agents be allowed to change company facts on their own?
  • How do you keep AI agents' knowledge of a company up to date?
  • What should stay out of an AI agent's company memory?

Direct answer

Company memory is what AI agents keep about a business between sessions: what it sells, what it may claim, its proof and its rules. Agents read it before they write, review or grade anything. When many people and agents share it, the hard part is deciding who may change a fact, making sure every agent reads the same version, and keeping out what doesn't belong.

We're rebuilding Corporate Context, the memory SolCrys agents keep about each customer's company, around four rules. They also work as a check for any team running more than one agent on brand work:

  • Rank the writers. A scheduled job can't overwrite a fact a person confirmed. It can propose a change; a person decides.
  • Give every reader the same version. The agent that drafts and the check that grades read the same version of the facts, assembled the same way.
  • Store facts, with their sources. Choices, your own grades and unannounced plans stay out.
  • Write back what you learn. Anything that researches the company files what it finds.

What Anthropic's study found

On Nov. 6, Anthropic published The components of agent memory, the clearest public account I've read of how an agent keeps what it learns between sessions. It describes four layers: a searchable log of past sessions, notes the agent writes, representations such as wikis, and a small block of context loaded into every session. It also describes "dreaming", a background pass in which the agent rereads its logs, corrects its notes against them and reorganizes what it keeps.

Two findings matter for anyone storing facts about a business. More memory isn't better memory: in a Pokémon Red run, a model that wrote 413 memory files earned one badge, and a newer model that kept about ten earned four. And shared memory loses facts when writers collide. When several agents wrote contract terms into one shared table, they overwrote one another's work, and the brief built from it kept 41 of 57 graded facts. With one agent per contract quoting the terms verbatim, all 57 survived.

Three kinds of memory

Put memory of a task, of a person and of a company side by side. What changes most is who writes and who reads.

Memory of a taskMemory of a personMemory of a company
Who writes itThe agent doing the workAn assistant, from what the person tells itMarketing, product and legal teams, the agents they direct, and scheduled jobs
Who reads itThe same agent, next sessionThat assistantEvery agent that acts for the company: writers, reviewers, site builders, the checks that grade AI answers
Who settles a conflictThe latest result the agent has checkedThe person's own wordsWhat the company has approved; a person outranks a scheduled job
What makes it staleThe task's environment changesThe person's life changesThe company launches, hires, raises money and renames things

Rule 1: rank the writers

When one agent works on a task, its memory has one writer: that agent. A company memory has many. A product marketer rewrites a positioning page, an agent drafting a blog post asks someone to confirm an integration, a scheduled job picks up last week's launch. Without an order among them, the last writer wins, and facts disappear, as they did in the contract experiment.

Ranking them is what makes automation safe to switch on. When a scheduled job disagrees with a fact a person confirmed, it leaves a proposal beside it, and nothing changes until a person accepts it. A team that can see and undo every machine write can afford to let machines write.

Rule 2: give every reader the same version

A company memory has more readers than writers. At SolCrys, the same Corporate Context grounds the agents that draft content, the audit that reviews pages, and Answer Accuracy, which grades whether an AI engine described the company correctly.

If each reader put the memory together on its own, with its own order, its own length limit and its own idea of which copy of a page is current, a writer and a grader could disagree about the company even though nobody changed a fact.

So the assembly belongs with the memory too, and each reader's job decides only which parts it gets. A grader needs the approved description. A writer needs that plus the detailed facts and the voice rules. Anthropic notes that one wrong note in the top layer reaches every session. In a shared company memory, one wrong fact reaches every agent.

Rule 3: store facts, with their sources

The most useful decisions were about what to keep out.

  • Choices. Which questions to track and which rivals to measure share of voice against are decisions a team makes per market or product line. In SolCrys they belong to a workspace, while one Corporate Context serves every workspace in the organization. Stored as company facts, preferences would read as truth to every agent.
  • Your own grades. Answer Accuracy grades engine answers against the memory. If those grades flowed back in, the memory would drift toward what the grader already believes, and the check would end up confirming itself.
  • Unannounced plans. Every agent that reads company memory writes for someone, so anything in it can end up quoted. A roadmap item in memory is one draft away from a public page.

Every fact keeps its source

What does get in carries its source. When a machine adds a fact, the fact has to be checkable against the page it came from: a number must appear in the source, a quote must be word for word, a customer must be named, and the link and date come from the source itself. Anything that fails stays out. For why sourced, current facts decide what AI gets right about a brand, see Why grounding depth decides whether AI gets your brand right.

Rule 4: write back what you learn

Most company memory is written once, at setup, and then read for months while the company launches products, signs partners and publishes case studies. Anthropic's study names the same drift from the agent's side: memory goes out of date as the environment changes, and the study suggests the background pass may need to focus on what is likely to change.

For a company, most of what changes is announced in public: in its newsroom, on its blog and in press coverage. Agents that already read those sources should file what they find, with the link, under the first rule. When a writing agent asks a person to confirm a fact for a draft, the answer should go into memory so the next draft doesn't ask again. Every agent that learns something about the company should file it the same way.

Where Corporate Context stands today

Corporate Context is set at the organization level: one memory of the company, kept as pages that every workspace shares. People edit it in the dashboard. Agents connected through the SolCrys MCP server can read it and propose changes for a person to review. Every change shows who made it, and any page can be restored to an earlier version. When SolCrys builds Corporate Context automatically at setup, it never overwrites a page a person has edited; it leaves a replacement draft instead. Answer Accuracy grades engine answers against it, and the grades don't flow back in.

FAQ

How big should a company's memory be?

As small as the jobs that read it allow: distilled pages by topic, each fact stated once, with the detail left in the sources each fact links to. In Anthropic's study, one wiki grew to 1.77 times the size of its source files, a sign that it had abstracted almost nothing. At company scale an agent can list the pages and read the ones its task needs, so we haven't built a search index. We'll add one when a writer can no longer fit what its task needs.
